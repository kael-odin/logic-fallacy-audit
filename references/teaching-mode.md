# 教学模式

教学模式的目标是让学习者能够自己重建论证、发现断点并修正结论，而不是记住更多谬误名称。

## 1. 适用场景

- 课堂练习与作业讲评。
- 写作、辩论和媒体素养训练。
- 对一个短论证做分步讲解。
- 为同一谬误提供正例、反例和边界案例。

## 2. 教学节奏

推荐使用六步：

1. **看原文**：只展示必要引文。
2. **找结论**：用中性语言重述作者想证明什么。
3. **补前提**：写出显式前提和最少量的隐含前提。
4. **找断点**：用普通语言说明结论为何还不能推出。
5. **给边界**：说明什么情况下原推理可能合理。
6. **改写与练习**：给出可检验版本，再让学习者处理新例子。

先遮蔽答案，再给提示。不要在同一屏先展示谬误名称，否则学习者容易从标签倒推分析。

## 3. 难度层级

| 层级 | 任务 | 提示程度 |
|---|---|---|
| 入门 | 识别结论、理由和一个明显断点 | 给出候选结构和定义 |
| 进阶 | 区分相邻谬误，补隐含前提 | 只给一个诊断问题 |
| 边界 | 判断是否真的构成谬误 | 给出多个竞争解释 |
| 迁移 | 把修复方法用于新主题 | 不给标签，只给目标 |

## 4. 讲解语言

- 一句话只解释一个推理步骤。
- 先使用普通语言，再给正式名称。
- 例子应原创、低争议、可公开。
- 对错误答案说明“哪一步偏离”，不要评价学习者能力。
- 明确区分事实真假、证据不足和推理无效。

## 5. 标准答案结构

每个答案至少包含：

- 主判 ID；
- 结论和前提；
- 断点机制；
- 一个相邻但不主判的概念；
- 一个边界或反例；
- 一条会改变判断的证据；
- 一个更强改写。

示例：

```text
主判：`hasty-generalization`
机制：三个人来自同一项目，不能代表整个代际。
边界：若作者只描述这三个人，结论范围应随之下调。
改变判断：代表性离职数据可能支持更窄的岗位适配结论。
改写：在这一个项目中，三名应届生半年内离职；现有证据不足以评价整个代际。
```

## 6. 出题原则

- 每道题只设置一个主要断点。
- 允许存在相邻概念，但答案必须解释为什么不是主判。
- 负样本要足够清楚，避免把语气强硬当谬误。
- 不在题干中加入真实隐私、政治仇恨或可识别个人信息。
- 一次练习不超过 5 个主要问题。
- 同一组练习要覆盖不同推理任务，不只考名称记忆。

## 7. 反馈顺序

1. 指出学习者已经正确重建的部分。
2. 定位第一个影响结论的断点。
3. 提供最少量提示。
4. 让学习者自己改写。
5. 最后再给正式谬误名称和扩展阅读。

## 8. 正式报告兼容

Teaching 报告仍遵守六个核心报告章节、原文依据、判定标签和置信度。可以额外增加：

- `## 分步讲解`
- `## 对照例子`
- `## 练习题`
- `## 答案`

保存为 Markdown 后使用：

```bash
python scripts/report_lint.py report.md --profile teaching --strict
```

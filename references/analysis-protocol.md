# 分析协议

本协议规定从原文到报告的完整路径。目标是稳定地解释“推理在哪里断”，而不是尽可能多地贴出谬误名称。

## 1. 任务边界

可以做：

- 重建论证结构。
- 评估演绎有效性与归纳支持。
- 识别相关性、预设、歧义、因果、统计、解释和辩证问题。
- 区分逻辑问题、证据问题、修辞问题与事实争议。
- 给出置信度、反例和修复条件。

不能只靠文本确定：

- 结论在现实中一定真或假。
- 发言者的真实动机或人格。
- 被省略数据是否其实存在。
- 讽刺、转述、虚构角色是否是作者本人立场。
- 复杂统计结论是否可复现。

遇到这些限制时，写明缺少什么以及该证据会怎样改变判断。

## 2. 输入整理

先标记文本类型：

| 类型 | 处理方式 |
|---|---|
| 作者直接论述 | 按正常论证分析 |
| 引用或转述 | 区分“引用者立场”和“被引用者立场” |
| 虚构、段子、反讽 | 先判断文本功能，避免按字面立场定罪 |
| 对话争论 | 分开各方主张、回应对象与未回答的问题 |
| 宣传或广告 | 同时检查命题证据和说服技术 |
| 片段 | 降低置信度，列出上下文缺口 |

把较长输入切成“一个结论及其支持理由”的论证单元。不同段落可能在证明不同结论，不能混成一个论证。

反问、俗语、网络梗和省略句先标为“修辞或会话行为”。如果它们只表达情绪，不强行改写成命题；如果它们承担了“理由 → 结论”的功能，再给重建版本并标记依据。

## 3. 句子角色

逐句或逐段标记角色：

- `事实主张`：可以用证据检验。
- `价值判断`：涉及应然、好坏、公平或优先级。
- `定义主张`：规定词义、分类标准或边界。
- `因果主张`：声称某因素产生、促成或阻止某结果。
- `解释主张`：声称哪种机制最好地说明已有事实。
- `预测主张`：声称未来状态。
- `让步`：承认对方某一点。
- `限定`：说明范围、例外或概率。
- `修辞`：比喻、反问、讽刺、重复、节奏或情绪表达。

同一句可能包含多个角色。分开处理后再看它们如何组成论证。

## 4. 结论与前提

先找作者希望受众接受的最终主张。不要把支持理由误写成结论。

推荐使用以下结构：

```text
最终结论：
  C1 ...

显式前提：
  P1 ...
  P2 ...

必要隐含前提：
  A1 ...（重建，不是原话）

支持关系：
  P1 + P2 + A1 ⇒ C1

限定与例外：
  ...
```

如果存在多个可能结论，保留最合理的两个版本并说明选择理由。

## 5. 最善意重建

在判定谬误前，尝试让论证成立：

1. 补充最少量的常识前提。
2. 把模糊词解释成最合理版本。
3. 区分作者的强主张与弱主张。
4. 如果作者只证明了一个较窄结论，不要把它扩写成极端结论。
5. 若仍无法成立，保留失败版本作为分析对象。

最善意重建不等于替作者补上任意证据。补充内容必须满足：

- 是让结论跟随前提所必需；
- 有文本线索或领域常识支持；
- 不能悄悄加入作者明确否认的内容。

## 6. 判断推理任务

不同论证使用不同标准：

| 推理任务 | 核心问题 | 常见失败 |
|---|---|---|
| 演绎 | 前提真时，结论是否必然真 | 否定前件、中项不周延 |
| 归纳 | 样本是否足以支持一般化 | 以偏概全、选择偏差 |
| 因果 | 是否有机制、时序、对照和替代解释 | 事后归因、单因解释 |
| 统计 | 基准率、样本、条件概率和不确定性是否处理正确 | 基准率忽视、检察官谬误 |
| 解释 | 哪个假设最能说明证据，是否可检验 | 不可证伪、异常猎取 |
| 定义 | 词义是否稳定、是否偷换 | 偷换概念、说服性定义 |
| 规范 | 价值前提是否明确，事实与应然是否分开 | 实然推应然 |
| 政策 | 目标、效果、副作用、替代方案和可行性是否比较 | 虚假两难、完美方案谬误 |

## 7. 四层评估

### 7.1 形式层

只在存在明确演绎推理时使用。

检查：

- 论证形式是否有效；
- 词项是否保持同一含义；
- 量词、条件和模态的辖域是否正确；
- 结论是否超出前提。

一个有效论证仍可能有假前提。

### 7.2 证据层

检查：

- 证据与结论是否相关；
- 样本是否代表目标总体；
- 证据是否足以支撑主张强度；
- 是否遗漏反例、替代解释和不确定性；
- 数据解释是否符合统计定义。

强结论需要更强证据，不能仅靠一个轶事。

### 7.3 辩证层

检查：

- 谁提出主张，谁承担初始举证责任；
- 是否回答了对方法律；
- 是否循环、转移目标或封死反证；
- 是否公平引用对方观点；
- 是否存在不允许对方提出可检验反例的结构。

### 7.4 修辞层

检查：

- 语言是否把未证明内容预设为事实；
- 情绪是否取代了理由；
- 二元框架是否压缩了合理选项；
- 重复、节奏和身份信号是否增加不该有的可信度；
- 说服策略是否与论证质量分离。

修辞不自动等于谬误。只有它造成推理替代、证据缺失或公平讨论受阻时，才升级为实质问题。

## 8. 谬误匹配

按以下顺序匹配：

1. 描述实际失败：结论跳步、证据不相关、词义变化、样本不足、责任错置。
2. 在目录中搜索机制关键词，而不是只看名称。
3. 选择最具体、解释力最强的条目。
4. 一个结构只给一个主标签，其他概念放“相关但不主判”。
5. 如果任何条目都不能精确匹配，用普通语言描述问题。

不要为了使用目录而制造匹配。

## 9. 误报复核

每个候选发现至少回答：

- 原文中哪一段真正承担了推理？
- 是否存在更强的善意解释？
- 该语境是否让身份、权威、情绪或历史变得相关？
- 如果补上哪一条事实，这个推理就可能成立？
- 结论强度和证据强度是否被混淆？
- 该问题影响最终结论，还是只影响一个旁支？
- 两个标签是否在描述同一个断点？

无法通过复核时，标记为 `不构成谬误` 或降低为 `较可能`、`语境相关`。

## 10. 严重度

本仓库用“影响”而不是“邪恶程度”排序：

| 等级 | 含义 |
|---|---|
| `阻断` | 主结论依赖该断点，当前无法成立 |
| `重大` | 结论可能成立，但关键支持明显不足 |
| `局部` | 某个例子或支线有问题，主论证还有其他支持 |
| `表达` | 主要是语言、框架或修辞风险 |

严重度高不代表发言者主观上故意欺骗。

## 11. 长文本处理

- 按论证单元拆解，不为全文强行找一个结论。
- 最多列 7 个主要发现；其余合并为重复模式或附录。
- 优先主结论上的 `阻断 / 重大` 问题。
- 同一机制在不同句子重复出现时合并，并引用代表句。
- 作者给出多条独立论证时，先评估是否至少一条成立。

短文本使用 `full` 时采用相反约束：

- 少于 250 个中文字符或只有一个论证单元，最多列 4 个主要发现。
- 同一逻辑断点只保留一个主标签，其他名称放入“相关但不主判”。
- 不为凑数量把一个反问拆成多个相邻谬误。
- 如果只有表达、修辞或证据不足，但没有明确谬误结构，应如实写“未发现稳定谬误模式”。

## 12. 事实核验分离

当文本包含可核验事实，但没有提供来源：

1. 标记为“事实状态未核验”。
2. 不因缺少引用就判定事实为假。
3. 分析该事实若为真，是否足以支持结论。
4. 如用户要求联网核查，再另列“事实核验”部分并引用来源。

逻辑分析不替代事实调查。

## 13. 输出前最后检查

- 是否先重建了论证？
- 是否每题都有原文引用？
- 是否把“论证错误”与“结论真假”分开？
- 是否至少做了一次善意解释？
- 是否说明何种新证据会改变判断？
- 是否用了最适合的标签，而不是最多的标签？
- 是否把不确定性写清楚？

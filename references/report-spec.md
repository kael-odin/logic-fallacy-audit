# 报告规范

报告的目标是让读者看懂一个论证如何工作、在哪一步失去支持，以及怎样把它改成可检验的论证。

## 1. 顶部元信息

正式报告建议包含：

```text
分析模式：quick / full / debate / teaching / explainer
文本类型：论述 / 对话 / 广告 / 政策提案 / 媒体转述 / 其他
分析范围：用户提供的文本及明确背景
总体判断：稳健 / 局部可修 / 核心支持不足 / 无法判断
源文件定位：文件名与 SHA-256（如可计算）
```

`无法判断` 是合法结论，不应为了显得专业而强行定性。

## 2. Quick 模式

适用于短句、单独观点或少于 250 个中文字符的文本。

最多输出：

1. 一句话判断。
2. 论证结构简表。
3. 1–3 个主要问题。
4. 一个更强的改写。
5. 一句边界说明。

Quick 模式不省略原文证据和置信度。

## 3. Full 模式

必须包含以下一级章节：

```markdown
## 结论摘要
## 论证地图
## 关键问题
## 反向检验
## 改写建议
## 边界说明
```

英文报告使用 [report-template.en.md](../assets/report-template.en.md) 的对应标题和字段。两边术语以 [glossary.md](glossary.md) 为准。

可按需要增加：

- `## 事实状态`
- `## 语言与修辞`
- `## 未回答的问题`
- `## 可继续追问`

不要增加没有证据支撑的“人格分析”“动机分析”或“可信度总分”。

### 3.1 Explainer 模式

`explainer` 与 Full 使用相同的六个必需章节和问题卡字段，但面向普通读者或短篇逻辑解说。推荐节奏：

1. 用原文中真正产生张力的句子开场；
2. 中性重述对方的表面主张；
3. 一次只揭示一个隐藏前提；
4. 说明哪一个推理连接现在没有成立；
5. 给一个只替换关键变量的最小反例；
6. 补上最强反方解释和可能不是谬误的边界；
7. 用更窄、可检验的版本收束。

模板见 [report-template.explainer.md](../assets/report-template.explainer.md)，样例见 [explainer-report.md](../examples/explainer-report.md)。

`explainer` 可以附加 `## 解说节奏` 或 `## 口播层`，但正式章节不得省略。视频化表达不能把 `较可能` 改写成 `一定`，不能编造对话、动机或专家原话，也不能删除误判边界。

## 4. 结论摘要

写 2–4 句：

1. 先总结作者想证明什么。
2. 再指出最主要的逻辑瓶颈。
3. 最后说明问题影响主结论还是局部例子。

不写“作者完全不懂逻辑”一类整体化评价。

## 5. 论证地图

至少给出：

| 项目 | 内容 |
|---|---|
| 最终结论 | 用中性语言重述 |
| 显式前提 | 原文直接给出的理由 |
| 隐含前提 | 为使结论成立所必需且未明说的假设 |
| 隐含前提的重建依据 | 文本线索、必要逻辑连接或领域常识 |
| 推理类型 | 演绎、归纳、因果、统计、解释、规范或政策 |
| 当前缺失环节 | 目前最关键的证据或定义缺口 |

当有多个结论时，分别编号 `C1`、`C2`，前提编号 `P1`、`P2`，隐含前提编号 `A1`、`A2`。

隐含前提必须标记为“重建”，不能让读者误以为它是原话。

## 6. 关键问题

每个问题使用固定字段：

```markdown
### 1. [问题标题]

**原文**
> “……”

**判定**
`确认` · 稻草人谬误 · 置信度：高

**机制**
作者先把对方主张替换为更强版本，再攻击替换后的版本。

**为什么结论还不能成立**
被攻击的版本不是对方实际主张；即使这个强版本失败，原主张仍未得到评估。

**影响**
`阻断`：主结论直接依赖这个错误替换。

**边界**
如果对方后续确实提出过更强主张，需要引用相应原文。

**相关但不主判**
`false-dilemma` 也可能相邻，但这里的主要断点是被攻击的主张并非对方主张。

**修复条件**
准确复述原主张，并回应其最强版本。
```

当结论是“未发现稳定谬误”时，也应提供一张 `不构成谬误` 的问题卡，说明善意解释、边界和当前证据为何不足以命名谬误。
此时影响等级使用 `无`，不要为了填表把稳健论证写成 `表达` 或 `局部` 问题。

问题数量建议：

- Quick：1–3 个。
- Full：通常 2–7 个；短文本或单一论证单元最多 4 个主要发现。
- 超过 7 个时，保留主问题，把重复模式合并。

排序：

1. 对主结论影响最大。
2. 逻辑上最基础。
3. 证据上最容易验证。

## 7. 判定标签

| 标签 | 使用条件 |
|---|---|
| `确认` | 文本结构清楚显示该模式，善意解释不能消除 |
| `较可能` | 存在明显线索，但缺上下文 |
| `语境相关` | 只有在特定对话责任或证据条件下才成为问题 |
| `不构成谬误` | 经复核后，该模式合理或只是修辞 |

标签描述的是“当前文本证据下的判断”，不是永久裁决。

## 8. 置信度

置信度必须解释：

- `高`：原句、论证关系与模式都明确，替代解释较弱。
- `中`：模式明显，但存在一到两个重要上下文缺口。
- `低`：片段、转述、多义句或无法确定作者立场。

不要把多个低置信度猜测相加成高置信度结论。

## 9. 反向检验

`## 反向检验` 必须包含四项：

1. **最强版本**：替作者补足最合理的隐含前提和证据。
2. **反例或测试**：哪种现实案例会使推理失败。
3. **替代解释**：至少一个能同样解释原文事实的竞争解释。
4. **可能误判**：分析者可能错在哪里，哪些新信息会改变判断。

这一节用于约束分析者，不是替作者辩护的礼貌装饰。

## 10. 改写建议

改写必须：

- 保留原作者的合理目标；
- 把结论收窄到证据支持的范围；
- 明示因果或统计假设；
- 加入可检查的验证条件；
- 不把分析者的观点冒充为作者观点。

推荐格式：

```text
在[范围]内，已有[证据]支持[收窄结论]。
这仍依赖[关键假设]。
如果[验证结果]出现，结论可加强；如果[反例]出现，应撤回或修改。
```

## 11. 政策与规范论证

涉及“应该”时额外区分：

- 目标是否合理；
- 手段是否有效；
- 副作用是否可接受；
- 是否有更小成本的替代方案；
- 谁承担成本、谁获得收益；
- 事实前提与价值排序是否被混在一起。

不要仅凭事实描述自动推出政策结论。

## 12. 事实状态

如文本包含事实主张，可加一节：

| 主张 | 当前状态 | 需要的证据 |
|---|---|---|
| ... | 未核验 / 已提供来源 / 与给定材料冲突 | ... |

未联网或未获授权时，明确写“未做外部事实核验”。

## 13. 边界说明

结尾说明至少一项：

- 分析只覆盖用户提供的片段。
- 没有核验文中事实。
- 无法推断作者动机。
- 谬误判断不证明结论真假。
- 专业领域结论需要领域数据或专家复核。

## 14. 禁止输出

- 没有原文依据的“谬误数量排行榜”。
- 把对方一句话心理分析成“控制欲”“恶意”“认知水平低”。
- 以“逻辑分”精确到小数的方式制造伪科学感。
- 只列名称、不解释机制。
- 将事实真伪与论证有效性混为一谈。
- 复制用户大段文字；引用必要片段即可。

## 15. 长文本与行号引用

长文本保存为 UTF-8 文件后，先运行：

```bash
python scripts/fallacy_cli.py segment path/to/source.txt --json
python scripts/fallacy_cli.py locate path/to/source.txt --quote "需要引用的原文"
python scripts/report_lint.py report.md --profile full --strict --source path/to/source.txt --require-locators
```

路径写成 `-` 时，`segment` 从标准输入读取文本。

有问题卡时使用：

```markdown
**原文**

> [L12-L14] “需要引用的原文”
```

行号对应规范化后的源文本。报告元信息记录 SHA-256；源文本内容改变后，旧行号不能继续使用。节选、字幕清洗和网页提取必须说明删除了什么，不能把处理后的文本冒充完整原文。

单一位置且没有省略号时，校验器会检查引文文本是否存在于声明行区间。多位置引用和含省略号的压缩引用目前只核验行号范围。

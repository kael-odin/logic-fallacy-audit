# 长文本与源文件定位

长文本分析先解决“在哪里说”，再解决“论证是否成立”。本流程使用确定性行号和精确引文，不把自动分段当成逻辑结论。

## 1. 保存源文本

使用 UTF-8 文本文件保存原文。命令会规范化 BOM 与换行符，并为规范化后的文本计算 SHA-256。

```bash
python scripts/fallacy_cli.py segment path/to/source.txt --json
```

从标准输入读取时，把路径写成 `-`：

```bash
Get-Content path/to/source.txt -Raw | python scripts/fallacy_cli.py segment - --json
```

JSON 包含：

- `sha256`：源文本指纹；
- `line_count` 与 `char_count`；
- 每个候选块的 `id`、起止行、字符范围与原文。

`segment` 默认按空行分隔段落。`--max-chars` 只在段落过长时按句末标点继续切分；切分结果仍只是候选块，不是自动认定的论证单元。

## 2. 定位引文

```bash
python scripts/fallacy_cli.py locate path/to/source.txt --quote "需要引用的原文"
```

输出格式：

```text
[L12-L14] chars=340-392
```

查找使用规范化后的精确文本匹配，返回所有出现位置，包括重叠出现。引文包含换行时，应保留换行。

## 3. 报告引用格式

获得行号后，问题卡使用：

```markdown
**原文**

> [L12-L14] “需要引用的原文”
```

顶部元信息记录：

- 源文件名称；
- 源文本 SHA-256；
- 分析是否覆盖全文；
- 是否需要外部事实核验。

行号指向规范化文本。只要源文件内容变化，SHA-256 就会变化，旧报告不能继续声称对应同一版本。

## 4. 分段与论证单元

候选块不等于论证单元。分析时继续执行：

1. 为每个候选块标注句子角色。
2. 找出它支持的结论。
3. 合并支持同一结论的相邻块。
4. 分开证明不同结论的段落。
5. 在报告中保留每个主要结论的引文来源。

同一段可能包含让步、限定和反例，不应只因为出现转折词就拆成独立论证。

## 5. 网页与字幕清洗

如果用户提供网页或字幕文本，清洗时必须保留审计痕迹：

- 删除导航、推荐、登录提示和无内容页脚。
- 保留标题、作者、发布时间和必要上下文。
- 保留字幕时间戳或行号。
- 不静默合并重复字幕。
- 修正明显 OCR 错误时保留原词或列出映射。
- 不把删除内容后的文本冒充完整原文。

本仓库不内置未经授权的视频、网页或字幕批量抓取器。

## 6. 长文报告约束

- 按论证单元分析，不为全文强行找一个结论。
- 主要发现按 `阻断 / 重大 / 局部 / 表达` 排序。
- 最多保留 7 个主要发现，其余合并或放入附录。
- 每个主要发现至少有一个 `Lx-y` 原文位置。
- 引用源文件时保留 SHA-256，避免报告与原文版本脱节。
- 如果源文本只是节选，降低置信度并声明缺失上下文。

## 7. 边界

行号工具不判断段落是否真的构成论证，也不修正语义错误。它只提供稳定的来源位置、字符范围和文本指纹。逻辑判断仍由分析协议、误报防线和人工 rubric 完成。

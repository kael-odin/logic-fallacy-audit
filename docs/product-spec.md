# 产品规格

## 1. 产品定义

Logic Fallacy Audit 是一个面向中文与英文文本的论证分析 Skill。输入一段论述、对话、广告、政策说明或媒体转述，输出可复核的逻辑分析报告。

产品核心不是“识别最多谬误”，而是稳定回答四个问题：

1. 这段文字到底在证明什么？
2. 结论依赖哪些没有说出的前提？
3. 证据和推理是否足以支持该结论？
4. 补什么证据、改哪句措辞，论证会更强？

## 2. 目标用户

- 内容创作者：检查口播稿、评论稿与辩论稿。
- 编辑与研究者：区分事实争议、证据不足和论证无效。
- 学生与教师：学习论证结构和谬误边界。
- 普通读者：抵御营销、宣传、带节奏和低质量争论。
- AI Skill 使用者：获得结构化、可复用、低臆测的分析流程。

## 3. 使用场景

| 场景 | 重点 |
|---|---|
| 社媒长文 | 结论、隐藏前提、以偏概全、情绪替代证据 |
| 短视频口播 | 引语、节奏、话术与论证断点 |
| 评论区争论 | 稻草人、人身攻击、举证转移、海狮式追问 |
| 政策提案 | 目标、机制、成本、替代方案、价值前提 |
| 统计报道 | 基准率、样本、条件概率、平均数和多重比较 |
| 营销广告 | 权威、流行、证言、FUD、框架操纵 |
| 阴谋论式推理 | 异常猎取、不可证伪、证据标准不对称 |

## 4. 五种模式

### Quick

用于短句和单一主张。输出一句话判断、结构简表、1–3 个问题和一个改写。

### Full

默认完整报告。包含结论摘要、论证地图、问题卡、反向检验、改写与边界。

### Debate

在 Full 基础上强调：

- 对方最强版本；
- 可公开引用的反驳句；
- 对方可能怎样回应；
- 什么证据会改变判断；
- 如何避免把逻辑批评升级为人格冲突。

### Teaching

用较少术语、更多步骤和对照例子解释为什么某一步不成立。输出应包含：

- 分步讲解；
- 一个更弱但可接受的版本；
- 一个仍然过强的版本；
- 练习题与可展开答案；
- 会改变判断的证据。

教学模式不得把答题表现转化为人格、智力或动机评价。

### Explainer

面向“逻辑科普解说”和“短篇口播式拆解”。在 Full 的证据标准上，把信息顺序改为：

1. 引用最能暴露断点的原句；
2. 中性重述表面主张；
3. 逐层揭示隐藏前提；
4. 指出推理连接在哪里断开；
5. 做一个只改变关键变量的最小反例；
6. 给出最强反方解释和误判边界；
7. 用更窄、更可检验的版本收束。

Explainer 不复制具体创作者的口头禅、画面或逐字稿，不靠嘲讽和动机猜测制造效果。若用户进一步要求视频稿，正式报告与口播层必须分开。

## 5. 非目标

- 不是事实核查服务。
- 不是测谎或动机识别工具。
- 不是心理诊断工具。
- 不是自动内容审核裁判。
- 不宣称任何谬误列表在哲学上绝对完整。
- 不把“发现谬误”当作“结论为假”的证明。

## 6. 质量标准

| 指标 | 要求 |
|---|---|
| 原文依据 | 每个主要发现至少引用一个必要片段 |
| 来源定位 | 长文本记录 SHA-256，并尽可能给出 `Lx-y` 引用 |
| 论证先行 | 先重建，后命名 |
| 标签节制 | 一个断点一个主标签 |
| 置信度 | 与上下文完整度一致 |
| 反向检验 | 每份 Full 报告必须包含 |
| 解说边界 | Explainer 不得为了节奏省略证据、置信度或误判边界 |
| 事实分离 | 逻辑错误不直接判定事实真假 |
| 可操作性 | 修复建议必须可检查 |

## 7. 成功信号

- 读者能复述“结论依赖哪条隐藏前提”。
- 读者能指出哪项新证据会改变判断。
- 作者能根据改写建议提高论证质量。
- 报告没有把语气、身份或价值差异冒充为逻辑谬误。
- 对手能承认报告准确复述了其最强立场。

# 源文本映射工作流审查

## 审查范围

- 长文本按段落形成候选块。
- 规范化文本的行号、字符范围和 SHA-256。
- 精确引文查找与多行引用定位。
- 长段按句末标点切分的可控上限。
- CLI、测试、文档和报告引用规范。

## 实现

新增 `scripts/source_map.py`，只使用 Python 标准库。它提供：

- BOM、CRLF 和 CR 的确定性归一化；
- 段落候选块 `U1`、`U2`……；
- `Lx-Ly` 行号与字符范围；
- SHA-256 源文本指纹；
- 精确引文与重叠出现定位；
- 可选的长段句末切分。

CLI 新增：

```bash
python scripts/fallacy_cli.py segment examples/long-text-source.txt --json
python scripts/fallacy_cli.py locate examples/long-text-source.txt --quote "三个人的经历"
```

## 设计边界

候选块不是自动论证单元。空行分段和句末切分只降低长文处理成本，语义上的结论、前提和论证边界仍由分析流程判断。

引文查找采用规范化后的精确匹配。它不会自动改写错字、合并空白或猜测近义文本；找不到时以非零状态退出，避免生成虚假行号。

## 报告契约

长文本报告使用：

```markdown
> [L12-L14] “需要引用的原文”
```

源文件 SHA-256 记录在报告元信息中。源文本改变后，旧行号和旧指纹不能继续代表同一版本。

## 验证

自动测试覆盖：

- BOM 与 CRLF/CR 归一化；
- 段落块和行号映射；
- 长段句末切分；
- 多行引文；
- 全部精确出现位置；
- 重叠匹配；
- CLI JSON 输出；
- 缺失引文的失败状态。

发布前要求通过严格目录校验、生成目录检查、报告 lint、Ruff、完整单元测试和 Skill 规范校验。

当前完整单元测试为 46 项，CI 还会直接运行示例 `segment` 与 `locate`。
